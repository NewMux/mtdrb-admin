# Full Audit — September 2026

Branch: `claude/full-audit-jpqlz1`. Scope: security & multi-tenancy,
correctness & data integrity, quality/perf/tests. Every CRITICAL and HIGH
finding below was fixed and verified (`npm run typecheck`, `npm run lint`,
`npx vitest run`, `npm run build:deploy`) before being committed. MEDIUM
and LOW findings are documented as backlog, not fixed, per the agreed
scope for this pass.

This document replaces `launch_findings.md` and
`marketing_audit_visual_findings.md`, both superseded by the findings
here.

## How to read this report

Each finding has an ID, a one-line description, file:line references as
they stood at the start of this audit, and either a commit hash (fixed)
or "Backlog" (documented, not fixed). Line numbers in "Backlog" entries
may have drifted from later commits in this same audit; use them as a
starting point, not an exact address.

## CRITICAL findings — all fixed

### C1 — Mock backend shipped to production, selectable by hostname
**Was:** `src/supabaseClient.ts` picked a mock Supabase client (admin role,
`paid: true`, accepts any password) whenever `window.location.hostname`
looked like a private IP or `.local` host — trivially true for anyone
self-hosting behind nginx per `SELF_HOSTING.md`.
**Fix (`ae13979`):** Gated on `import.meta.env.DEV &&
VITE_FORCE_REAL_CLIENT !== "true"` instead — a build-time constant. Added
`scripts/check-dist-no-mock.mjs`, wired into `build:deploy`, which fails
the build if the mock marker survives into `dist/`.

### C2 — Invoice status casing mismatch: revenue read as zero
**Was:** Writers persisted `"Paid"`/`"Unpaid"` (capitalised); every
analytics reader filtered on lowercase `"paid"`. Confirmed against the DB
CHECK constraint: only lowercase is valid, and `"Unpaid"` isn't a valid
status at all.
**Fix (`ef1642d`):** One canonical `InvoiceStatus` union and
`src/utils/invoiceStatus.ts`, applied at every read and write site.
Deleted two dead components with the old casing baked in.

### C3/C4/C5 — VAT math inverted, discount-order wrong, revenue double-counted
**Was:** `AddInvoiceModal` computed VAT-inclusive tax as `amount * rate`
instead of extracting it; `NewInvoiceModal` applied VAT before discount in
the header total but after discount per line, so the two disagreed;
`BusinessOverview.tsx` summed `total + vat_total` for rows that already
included VAT, double-counting it.
**Fix (`2864e72`):** One money contract in `src/utils/invoiceMath.ts`
(discount on line net → VAT on discounted net → total = net + VAT), used
by both modals and every reader. 22 tests assert Σ(line totals) === header
total across inclusive/exclusive/discount combinations.

### C6/C7 — Fabricated financials
**Was:** The VAT return filed all-time totals under the current month's
period. Per-trainer "Revenue Generated" queried invoices with no trainer
filter, crediting every trainer with the whole gym's revenue; class
analytics divided gym revenue by trainer count and hardcoded `retention:
85`.
**Fix (`bfaae33`):** VAT return now files `currentPeriodVat`. Verified live
against the DB that `invoices` has no `trainer_id`/`class_id` column —
attribution is genuinely impossible with the current schema — so the
fabricated metrics were removed rather than patched. Deleted dead
`src/api/vat.ts`.

### C8 — "+4900% vs last month": comparing unrelated populations
**Was:** Dashboards compared *all currently-active members* against
*members who signed up last month* — two different populations, not a
month-over-month comparison.
**Fix (`fb0019d`):** New `src/utils/memberActivity.ts` approximates
point-in-time active-member counts from `join_date`/`expiry_date` (the
schema has no membership-history table), used to compare *active as of
last month's end* against *active now*.

## HIGH findings — all fixed

### H1 — Unlimited self-service trial reset
**Was:** `trial_end`/`current_period_end` were client-supplied and
unconstrained; replaying the signup upsert reset the trial indefinitely.
**Fix (`c4203f7`, migration `20260909150000`):** Both fields are now
computed server-side on every self-service write; a tenant that already
has a `trial_end` may not start a second trial. Verified against
`Subscribe.tsx` that this doesn't block the app's own legitimate flow.

### H2 — Paid-tier entitlement enforced only in the browser
**Was:** No RLS policy referenced `platform_subscriptions.status`; an
expired tenant kept full read/write with a valid JWT.
**Fix (`c4203f7`, migration `20260909150100`):** Added
`is_tenant_entitled()` and required it on INSERT/UPDATE for members,
invoices, expenses, and classes. **Verified live before writing this**:
10 of 15 tenants have no subscription row at all, so "no row" is treated
as entitled (grandfathered) rather than denied — a naive "no row = deny"
would have locked out most of the live tenant base. Only the one tenant
with an actually-lapsed trial loses write access.

### H3 — ~18 tables referenced in code, apparently missing from schema
**Resolved by verification, no fix needed.** Confirmed live: exactly 32
tables exist, all with RLS on; none of the ~18 "missing" tables
(`profiles`, `trainer_payments`, `vat_transactions`, etc.) exist as real
gaps. Every reference traced to dead code (deleted in the H6 commits) or
a call site that already catches `42P01`/`PGRST116` gracefully.

### H4 — Storage buckets: broken uploads, not open ones
**Was:** `AddTrainerModal.tsx` and `Settings.tsx` uploaded to
`trainer-documents`/`profile-pictures`/`attachments` buckets. Verified
live: none of these exist (only `expense-receipts`, `invoice-files`,
`task-attachments`, `gym-logos` do) — every trainer-document and
profile-picture upload was failing in production.
**Fix (`c4203f7`, migration `20260909150200`):** Created both buckets with
size/MIME limits and tenant-scoped RLS policies (`profile-pictures` write
requires `admin`, matching the `/dashboard/settings` route guard).
`AddTrainerModal.tsx` now scopes uploads under `documents/<tenant_id>/...`
and sanitizes `file.name` (previously interpolated unsanitized into the
storage path). `Settings.tsx` no longer falls back to an undefined
`attachments` bucket on failure.

### H5 — Committed SQL that reintroduces a cross-tenant takeover
**Was:** `fix_signup_rls.sql`, `complete_schema_v2.sql`,
`complete_schema.sql`, and 3 other files recreated the `user_metadata`-
based memberships policy that `20260817124613_launch_security_hardening.sql`
exists to remove.
**Fix (`c4203f7`):** Deleted `fix_signup_rls.sql`,
`fix_tenant_creation_rls.sql`, `fix_missing_policies.sql`,
`complete_schema.sql`, `complete_schema_v2.sql`. `schema.sql` is kept —
`DEPLOYMENT.md` documents it as the actual bootstrap path production was
built from; deleting it would break the documented setup process.

### H6 — 28,000+ lines of dead code, including live-mounted fabricated data
**Fix (`496d0eb`, `0a58854`):** Deleted 135 never-reachable files (37,282
lines total across both commits). The scan initially missed 26 files
hidden behind barrel re-exports (an `index.ts` doing `export {X} from
"./Y"` made the scanner think `Y` was "referenced" even when nothing
that imports the barrel ever pulls in `X`) — a second, more careful pass
traced actual named-import usage through each barrel and caught these,
including the 9 trainer modals with hardcoded `isProUser = true` (H16)
and `src/api/secureClient.ts` (582 lines of unused validation/rate-limit
scaffolding that implied inputs were checked when they weren't, since
`src/api/client.ts` — the client actually in use — never called it).

### H7/H8 — Swallowed Supabase errors rendered as zeros
**Fix (`c445fb4`):** Added `if (error) throw error` at ~20 sites that
destructured `error` off a PostgREST response and never checked it
(`SmartDashboardOverview.tsx`, `LiveKPITracker.tsx`, `AnalyticsTab.tsx`,
`TrainerPerformanceDashboard.tsx`, `SmartVatDashboard.tsx`,
`NewInvoiceModal.tsx`, `BusinessOverview.tsx`); added a `loadError`
banner to 5 dashboards that only `console.error`'d on failure.

### H9/H10 — Timezone-truncated date boundaries; unpaginated queries
**Fix (`3257a46`):** `src/utils/periodBoundaries.ts` computes month/week/day
boundaries via `date-fns-tz` with `Date.UTC` normalization for correct
rollover, replacing `toISOString().split("T")[0]` truncation that was
off-by-one in UTC+3 and excluded "today" from month-to-date figures.
`src/utils/fetchAllRows.ts` pages through PostgREST's 1000-row `.range()`
cap. Applied to `BusinessOverview.tsx`, `SmartDashboardOverview.tsx`,
`SmartVatDashboard.tsx`'s invoice fetch.
**Not yet applied** (see Backlog): `FinancialInsightsDashboard.tsx`,
`ClassAnalyticsTab.tsx`, `TrainerPerformanceDashboard.tsx`,
`AnalyticsTab.tsx`, `MemberEngagement.tsx`, `Analytics.tsx` still use the
old truncation/no-pagination pattern.

### H11/H12/H13/H14 — Wrong "live" status, false success toast, wrong deadline column, mislabeled trends
**Fix (`fb0019d`):** `LiveKPITracker.tsx`'s "members in gym" now requires
`status === "checked_in" && !check_out_time` (was `||`, counting anyone
who ever checked in). Weekly attendance now filters by class
`start_time` via a `classes!inner` join instead of booking `created_at`.
Removed the false "Report scheduled successfully!" toast so the honest
"delivery isn't set up yet" alert from `useSmartAnalyticsModal.ts` can
actually be seen. Standardized VAT filing deadline on the `due_date`
column (was split between `due_date` and `filing_deadline`). Relabeled
churn rate from "This Month" (it's cumulative) to "All Time"; made
`KPICard` genuinely trend-aware instead of a hardcoded green up-arrow.

### H15 — CSP blocked the payment gateway; no real payment could complete
**Fix (`bd985f6`):** Added `https://credimax.gateway.mastercard.com` to
`script-src`, `connect-src`, `form-action`, and a new `frame-src` in
`vercel.json` and all 3 CSP lines in `nginx.conf.template`. Also added
`https://*.ingest.sentry.io` to `connect-src` (L-severity finding, fixed
alongside since it was the same header) and fixed a `nginx.conf.template`
line that had `SUPABASE_DOMAIN` in `script-src` instead of `connect-src`.

### H16 — Pro-only features unlocked for every tenant by default
**Fix (`bd985f6`, `0a58854`):** 4 live analytics modals
(`PrintReportModal.tsx`, `ShareReportModal.tsx`, `ScheduleReportModal.tsx`,
`ExportReportModal.tsx`) changed `isPro ?? true` to `isPro ?? false`. The
9 trainer modals with hardcoded `isProUser = true` were confirmed dead
(reachable only through an unused barrel + demo wrapper) and deleted in
the H6 follow-up commit rather than patched.

## MEDIUM — documented backlog, not fixed

**Correctness:**
- BHD rounded to 2 decimals in POS receipts vs. 3 decimals elsewhere (`src/pages/POS.tsx:109`); the same discount-proration bug as C3/C4
  (`Math.max(subtotal,1)` breaks under 1.000 currency units) exists in
  `POS.tsx:310-313,437-440`, duplicated from the invoice modals, with zero
  test coverage on real money.
- Float money is never rounded before persisting to `NUMERIC`.
- MRR is month-to-date revenue, and `projectedRevenue` is that partial
  actual, not a projection (`FinancialInsightsDashboard.tsx:750,959`).
- N+1 `profiles` query per assignee (`SmartTaskAnalytics.tsx:1198-1204`).
- Hardcoded zeros rendered as measured risk findings
  (`SmartTaskAnalytics.tsx:1361-1376`).
- `subscriptionEntitlement.ts:24-32` revokes access the instant a paid
  user cancels, but grants forever when `current_period_end` is null.
- A fabricated `target: currentRevenue * 1.1` silently overrides the
  admin's saved target shown directly above it
  (`SmartDashboardOverview.tsx:327` vs `DashboardOverview.tsx:242-245`).
- VAT return "overdue"/"upcoming" derived from status, not dates, with an
  invented compliance score (`SmartVatDashboard.tsx:194-199,272`).
- A fake "Document reminder sent" toast on the live members table
  (`SmartMemberTable.tsx:234-236`).
- Missing tenant-scoping as defence-in-depth (RLS already covers these,
  but explicit scoping is cheap insurance) at `NewInvoiceModal.tsx:253-265`,
  `SmartTaskAnalytics.tsx:1200-1204`.
- H9/H10's remaining unconverted files, listed above.

**Security:**
- M1: `credimax-webhook` has no idempotency/replay protection and doesn't
  assert `order.amount` matches the pending checkout
  (`supabase/functions/credimax-webhook/index.ts:107-133`); period
  extends from `now` rather than `max(now, current_period_end)`.
- M2: the webhook logs the raw MPGS order object — masked PAN, cardholder
  name, customer email — into `activities.metadata`, readable by every
  trainer in the tenant (`:139,173`).
- M3: `activities` inserts have no role gate; any member can forge audit
  entries.
- M4: `get_lockout_threshold(text)` is `anon`-callable and returns a
  tenant-specific value — an account-existence oracle
  (`20260823161811_*.sql`).
- M5: password policy is enforced only in the browser.
- M6: the client-side permission model is looser than the DB's in places,
  showing controls that always fail at the RLS layer.
- M7: `src/types/roles.ts:52-58` fails *open* to trainer-level access on
  an unrecognized role string.
- M8: `_shared/cors.ts:2` is `*`.

## Quality / perf / tests — backlog beyond the H6 dead-code deletion

- **`tsconfig.json` excludes every test file**, so `npm run typecheck`
  never type-checks tests and `npm run validate` gives partial assurance.
  Fixing this is worthwhile but out of scope for this pass — it will
  surface pre-existing type issues in test files that need triage.

  `react-hooks/exhaustive-deps` (stale-closure risk).

  `react-chartjs-2` both in use; `@fullcalendar/*` and
  `react-big-calendar` both in use. Consolidating either pair would cut
  bundle size without a code-splitting change.

  coverage on money math (`invoiceMath`, `invoiceStatus`,
  `memberActivity`, `periodBoundaries`, `fetchAllRows`,
  `subscriptionEntitlement`) improved substantially this audit (115 → 173
  tests); POS money math (same discount-proration bug as C3/C4, see
  MEDIUM) still has none.
- **Repo hygiene**: `marketing_*.md` files at the repo root duplicate each
